You've been there. A test goes red in CI at 2 AM. The stack trace points to line 47 of a file you didn't write. The assertion message says expected: <true> but was: <false>. Congratulations — you now own a mystery.

What if the moment a test failed, an AI expert appeared in your console and said: "Here's the root cause, here's why it happened, and here's the exact fix"?

Java Failure Analyzer is a JUnit 5 extension that intercepts test failures and automatically sends the failure context to GitHub Copilot — then prints a structured diagnosis back to your console.

📦 github.com/jrpally/ai-powered-agent-failure-analysis-java

⚙️How it works

JUnit 5 has a little-known extension point called TestWatcher. It fires a callback every time a test fails. Java Failure Analyzer hooks into that callback:

1
Test fails — JUnit calls testFailed(context, throwable)
↓
2
Extension captures — exception, stack trace, test source, production source
↓
3
Sends to Copilot — the full context is crafted into a precise prompt
↓
4
Diagnosis printed — Root Cause · Analysis · Suggested Fix · Prevention

The key differentiator: the model doesn't just see a stack trace — it sees the actual source code that caused the problem, the same way a human reviewer would. SourceCodeLoader automatically finds the .java file for both the test class and the production class under test.

🖥️The output

When a test fails, this appears in your console — before you've even opened the file:

╔══════════════════════════════════════════════════════════════╗
║          🤖  GitHub Copilot — Failure Analysis              ║
╠══════════════════════════════════════════════════════════════╣
║  Test: stringReverseShouldWork                               ║
╠══════════════════════════════════════════════════════════════╣

  ## Root Cause
  The `reverseString` helper initializes the right pointer to
  `chars.length - 2` instead of `chars.length - 1`, leaving the
  first and last characters unswapped.

  ## Analysis
  For input "hello" (length 5), right starts at index 3 instead
  of 4. The swap loop never touches index 4 ('o'), producing
  "lleho" instead of "olleh".

  ## Suggested Fix
  Change:  int right = chars.length - 2;
  To:      int right = chars.length - 1;

  ## Prevention
  Add boundary tests with a 1-char and 2-char string to cover
  edge cases of the swap loop.

🚀Zero-friction setup

Option A — Annotate one class

@ExtendWith(FailureAnalyzerExtension.class)
class PaymentServiceTest {

    @Test
    void chargesCustomer() {
        // Any failure here → automatically analyzed by Copilot AI
    }
}

Option B — Activate for every test in the project

Add one line to src/test/resources/junit-platform.properties:

junit.jupiter.extensions.autodetection.enabled=true

The JAR ships a META-INF/services file that registers the extension via Java's service loader. That single property switches it on globally — no annotation needed on any test class. Then:

$ export GITHUB_TOKEN=ghp_yourPersonalAccessToken
$ mvn test

🔌Provider flexibility

The extension isn't locked to one AI backend. It resolves providers in priority order:

Priority 1
Custom Endpoint
Any OpenAI-compatible API — self-hosted LLMs included
Priority 2
GitHub Copilot
Exchanges your PAT for a short-lived session token automatically
Priority 3
GitHub Models
Uses your PAT directly — simpler, no token exchange
Priority 4
OpenAI
Drop in an OPENAI_API_KEY and it just works

🎛️Configuration without ceremony

Every option is a system property or environment variable — nothing to commit to your repository:

System Property Default What it does

🏗️The architecture

Five classes. Each with a single, clearly defined job:

FailureAnalyzerExtension
JUnit 5 hook — implements TestWatcher and orchestrates the analysis flow
CopilotClient
HTTP calls to the AI provider, handles token exchange and provider fallback
AnalyzerConfig
Reads system properties and environment variables with sensible defaults
FailureContext
Value object holding the exception, stack trace, and source code
SourceCodeLoader
Finds .java files on disk from standard Maven/Gradle project layouts

🏁Get started in 5 minutes

  1. 1
    Add the dependency
    <dependency>
  <groupId>io.github.failureanalyzer</groupId>
  <artifactId>java-failure-analyzer</artifactId>
  <version>1.0.0</version>
  <scope>test</scope>
</dependency>
  2. 2
    Enable auto-registration
    # src/test/resources/junit-platform.properties
junit.jupiter.extensions.autodetection.enabled=true
  3. 3
    Set your GitHub token
    $ export GITHUB_TOKEN=ghp_yourPersonalAccessToken
  4. 4
    Run your tests — and let something fail
    $ mvn test
# Watch Copilot diagnose the failure in real time
